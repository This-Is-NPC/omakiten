| FR-084 | Expose CLI `okt update` (introduced v0.20.0): in-binary self-update lifecycle triggered manually by the user. Pre-swap step takes a mandatory recovery snapshot via `recovery.BackupService` (factory wired lazily so `--check` and noop paths skip backup-dir resolution); backup failure aborts before any network IO. | NFR-028 | SQLite `NULL`-coercion is routed through `sqlutil.{NullStringOr, NullInt64Ptr, NullTimePtr}` helpers instead of inline `if v.Valid { … }` ladders. | NFR-030 | Project deletion is generation-safe and retention-safe: one pinned SQLite connection verifies a recovery image against `data_version` before and under `BEGIN IMMEDIATE`, then deletes project events and the FK cascade in that transaction. | NFR-031 | Release trust metadata is replay-resistant and fail-closed: all action/tool versions are immutable, only the signing job receives OIDC, manifest/provenance validation pins repository/tag/commit and the complete Linux/Darwin/Windows amd64/arm64 archive set, and no draft is published when signing, transparency-log proof, certificate-policy, digest checks, or either production strict installer fails against the freshly generated keyless bundles. ## Agent integration

The binary embeds one `omakiten` skill. Setup publishes it to shared or Claude Code destinations; project init can install it locally. Managed updates preserve foreign skills and uninstall removes only the owned entrypoint. `projects list` discovers registered project scopes; `command list` and `command resolve` expose configured playbooks through surface-gated operations. See [Agent integration](../agents.md), `internal/installer/skill.go`, `internal/cli/command.go` and `internal/operation/service_project.go`.
