Build only what the active hypothesis demands. Anything beyond gets a postit (followup comment, backlog task), not code. Generality, future-proofing, and "while I'm at it" cleanups belong to the next spike, not this one.

Bad: added a config flag for a feature nobody asked for yet, because "we might need it."
Good: shipped the simplest path that answers the hypothesis; opened a separate task for the flag if/when demand surfaces.
